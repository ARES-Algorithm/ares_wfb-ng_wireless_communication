# 通用 UDP 无线接口

```text
应用 A → 本地 UDP → WFB-NG → 无线 → WFB-NG → 本地 UDP → 应用 B
```

## 双向端点

| 角色 | 应用发送目标（WFB 监听） | 应用接收绑定（WFB 投递） |
|---|---|---|
| robot | 127.0.0.1:5642 | 127.0.0.2:5641 |
| controller | 127.0.0.1:5641 | 127.0.0.2:5642 |

数据流 ID 为 0x03（robot → controller）和 0x81（反向），不属于应用负载。
两端 data_tx/data_rx 按各自方向配对。不再提供旧控制、遥测或测试端口。

## 传输约定

- 单个 UDP 数据报是应用提交的传输单位。负载不加业务头，不解析负载内容。
- 对成功交付的数据报，应保持负载字节和数据报边界；不保证每个数据报都交付，也不保证顺序和唯一性。
- 每个接收端点应由一个应用绑定。不要用 SO_REUSEPORT 期待多进程都收到同一份数据。
- 两个方向共享实际射频资源；满速双向负载需要实测。
- 端口、地址和 stream ID 可以修改，须同步修改两端配置及各自应用端点。
- 适用的数据报上限取决于已安装 WFB-NG 版本、编译配置和运行参数；本工程不增加分片功能。
  小消息接入可先使用不超过 1200 字节的 UDP 负载，最终上限和吞吐需在目标环境确认。
- 无输入业务数据时不会生成合成业务流量；WFB 自身的会话/维护流量不属于应用数据。

## 参数归属

应用决定每秒提交多少包、每包多少字节。无线配置决定 channel、bandwidth、mcs_index、
wifi_txpower 和 FEC；底层不限制业务消息类型或应用框架。功率取值含义依赖网卡驱动。

当前 data_tx 使用 fec_k=2、fec_n=4，沿用迁移前该双向流的纠错配置。
加密/FEC 属于 WFB-NG 无线传输实现，应用不需要自行处理其无线封装。
